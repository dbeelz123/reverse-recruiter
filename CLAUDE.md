# Reverse Recruiter: working rules for Claude

Overview: [README.md](README.md). The full process: [docs/how-it-works.md](docs/how-it-works.md). Setup: [docs/setup.md](docs/setup.md).

**Personal settings go in `CLAUDE.local.md`** (git-ignored, read by Claude Code alongside this file): where the user's data folder is, their name and how they like to work. If the data folder isn't `my-data/` in this repo, pass `--data <folder>` to every script. Never write personal facts into this file, the engine or the docs.

## Data and folders
- All script paths come from `engine/paths.py`. Change a location there, never in individual scripts.
- **Every folder shows only working files.** When Claude replaces one of its own outputs (a newer report, resume draft or data file), the old one moves to that folder's `archive/` in the same step. Scripts ignore `archive/`.
- **Never put temporary or scratch files in the project or the data folder.** Use the session scratchpad. Delete anything generated by accident (e.g. `__pycache__`; run Python with `-B`).
- **Files the user supplies** (PDFs, resumes, profile exports): ask before moving or deleting them, except removals already approved through the removal prompt.
- `1-inbox/job-pdfs/` mirrors the user's saved jobs: PDFs stay at the top level across rounds. When the user unsaves a job, run the removal prompt.

## Standing rules
**One home per rule:** job criteria live only in `spec.json` (history in `changelog.md`); the round process lives in docs/how-it-works.md; how Claude works lives here.

- **Terminology:** the agent's question-and-answer step is **calibration** (it tunes qualifiers and disqualifiers). **Interview** means an employer interview only.
- **A save is a candidate, not a preference.** Don't infer preferences from saves; get them through calibration.
- **Criteria changes need the user's approval.** Propose; on yes, update `spec.json` and add a changelog row under a heading that carries `[round N]` (modes.py counts new rules per round from these headings).
- **Removal prompt:** when a job hits a dealbreaker or the user unsaves it, ask before removing it. The reason goes in `removed.json` and, if new, becomes a rule. Jobs with a 1st-degree connection are never removed automatically. Never remove a job just because of its company group or a possible repost; judge those in the round.
- **Re-screen at the end of every round:** judge every flag against all current jobs; real dealbreaker hits go through the removal prompt before the report.
- **Every round's report ranks every current job**, old and new; the previous report and its images move to `2-reports/archive/`.
- **Metrics every round:** `metrics.py --round N` after the re-screen and before `build_report.py`; log timing events at each stage boundary (`metrics.py --round N --event <stage>`). Then `precision.py --round N` (add new miss patterns to `searches.json` → triage_flow 3b) and `modes.py signals`.
- **Triage calls:** record `likely` on every batch card before the user decides (likely keep / lean keep / possible: <missing fact> / lean DQ / weak). Commit to a lean; "possible" only with a named missing fact.
- **Triage modes:** the mode is in `searches.json` → `mode`. Report the stability signals at each round's end; ask about switching only when `modes.py` prints ASK USER, and never switch on your own.
- **Strong keep / strong DQ:** when the user marks a triage row so, record it and give that job an in-depth calibration Q&A at the round's calibration.

## Profile and applications
- **`career-master.md` is the only source of claims.** Titles, dates and timeline never change. New facts go into it only after the user confirms them. `voice-guide.md` is style only; every time the user edits a draft, add the before/after to its "edits to drafts" table.
- **Resumes:** edit only a **copy**, with **Word tracked changes** (author "Claude"), keeping one page. Never change a version an employer already holds. When the user accepts and exports a new version: check it (no tracked changes left, one page, the PDF matches), archive the previous version, update references.
- **Profile text** (e.g. LinkedIn) is drafted as paste-ready text; the user edits their profile by hand.
- **Staleness gate:** before any kit work ("prep", "stretch review", "primer") and before telling the user to apply, run `staleness.py gate <job>`. On CHECK FIRST, give the link and wait. After every pasted saved-jobs page, run `staleness.py tracker <paste>`.
- **Every application kit starts with a stretch review** in chat; build only on the user's decision, and name only the gaps they chose.
- **Record every application step** the user reports (outreach, applied, response, interview, passed) with `pipeline.py record`, update the kit's `log.md`, and rebuild the queue (`pipeline.py queue`).
- **Interview primer:** "primer <company>" → `primer.py draft`, then the files by `engine/prompts/interview-primer.md`, then `primer.py check` must print PRIMER COMPLETE.
- **Interview loop:** record rounds with `interviews.py schedule`; afterwards run the debrief (`engine/prompts/interview-loop.md`), draft thank-you notes for the user to send, mark them `sent`. Check `interviews.py due` at the start of each session and mention anything owed.
- **Role Explorer:** research people only from full names the user gives, and only public, professional information; never guess identities from partial names. Mark findings confirmed or inferred, with sources.

## Outward-facing actions
- **Data gathering is manual:** work only from pages the user saved or pasted. No browser automation of job sites unless the user explicitly opts in.
- Nothing is sent, applied for or published by Claude. Drafts only; the user acts.
- **Public numbers** (e.g. the LinkedIn project) change only on the user's say-so and are always **per 100 job listings processed**, never raw totals.

## Engine changes
- Keep `engine/`, `docs/` and this file free of personal data and personal paths: say "the user", never a name.
- After any engine change, run `python -B engine/privacy_scan.py` (0 hits) and `python -B -m unittest discover -s tests` (all pass), and test on a **copy** of the data folder, comparing outputs before and after. Add a test for every bug fixed.
- Read and write data files only through `paths.read_json` / `paths.write_json` (clear errors, atomic writes); never delete outside the folder a file belongs to (`Paths.inside`).
- The pre-commit hook (`scripts/hooks/pre-commit`) blocks personal-data paths and anything the privacy scan finds; never bypass it.
